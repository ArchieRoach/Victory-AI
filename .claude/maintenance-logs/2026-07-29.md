**Accessibility + touch target — `FeedbackWidget.jsx` star-rating buttons**
The 5-star rating control (`[1,2,3,4,5].map(...)`) had no `aria-label` at all — a screen-reader
user tabbing through it would hit 5 unlabeled buttons with no indication it's a rating control,
unlike every other icon-only button in this same file (the floating trigger and the close button
both already carry `aria-label`). The buttons also had no explicit size (`text-2xl leading-none`

gap-1` row. Added `aria-label={\`Rate ${star} star${star > 1 ? "s" : ""}\`}` + `aria-pressed`
(matching `LiveChat.jsx`'s emote-picker-toggle `aria-pressed` convention) and the `touch-target`
class + flex centering, matching the drop-in fix pattern used repeatedly in prior passes (e.g.
2026-07-28's `PaywallPage` back button).

## Task 3: Debug Sweep

**Fixed — `ProfilePage.jsx`'s `handleLogout` had no error handling:**
`handleLogout` called `await logout()` (which calls Clerk's `signOut()` with no internal try/catch)
directly, with no wrapper of its own — unlike its two siblings in the same file,
`handleExportData` and `handleDeleteAccount`, which both already wrap their async work in
try/catch + `toast.error`. If `signOut()` ever rejects (network blip, already-invalid session),
the user clicks "Log out" and gets total silence: no toast, no navigation, nothing — an unhandled
promise rejection with zero user feedback. Wrapped it in try/catch with
`toast.error("Couldn't log out — try again")`, matching the plain-string `toast.error` convention
already used elsewhere in this same file (lines 113, 146, 166) rather than adding a new i18n key
across all 10 locale files for an edge-case error message.

Wrote a script-assisted sweep (not just grep) for every `async` function in `frontend/src` that
calls `axios`/`await` with **no** `try` and **no** `catch` anywhere in its body — surfaced 3 hits:
the `handleLogout` bug above (fixed), and `PushPrompt.jsx`'s `handleEnable` +
`ProfilePage.jsx`'s push-toggle `onCheckedChange`, both of which only call
`usePushNotifications`'s `subscribe()`/`unsubscribe()` — confirmed those two already catch
internally and return `false`/`undefined` rather than ever rejecting (verified in
`usePushNotifications.js`), so no gap there.
