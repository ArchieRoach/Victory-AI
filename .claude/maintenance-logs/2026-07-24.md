## Task 2: Security Audit

Full pass over `backend/server.py` (4308 lines, no commits landed since 2026-07-23's merge). Verified
route-by-route: auth coverage on all 114 handlers still matches the intentionally-public set from
prior days (register/login/logout, `/webhook/stripe`, static reference data, `/health`,
`/waitlist/signup`, `/ads/*`, `/onboarding/social-proof`, `/onboarding/partner-styles`); CORS still an

`/ai/generate-feedback` still pure local computation, no cost to gate.

**Fixed — `POST /emotes/generate` had no rate limit:**
2026-07-21's audit noted `/emotes/generate` and `/onboarding/generate-avatar` build unrated
Pollinations.ai image URLs and judged it too low-severity to touch, reasoning the image itself is
fetched client-side with no backend cost. That reasoning holds for the two avatar endpoints (both do
a single `update_one` on the calling user's own document — bounded, self-overwriting, no growth) but
doesn't fully cover `/emotes/generate`: it does an unbounded `insert_one` into `db.emotes` on every
call, and those emotes are listed in a public marketplace (`/emotes/{emote_id}/purchase`). An
authenticated user hammering this endpoint could spam-create unlimited DB documents and pollute the
public emote marketplace — a genuinely different cost profile from the avatar case. Added
`_rate_limited(f"emote_generate:{user_id}", 10, 60)`, matching the existing `posts:` (10/60)
convention for user-generated-content creation. Left the two avatar-regen endpoints as-is — 07-21's
reasoning still applies to those.

`python3 -m py_compile backend/server.py` passes.

On a failed `GET /drills/{dimension}`, the component only `console.error`'d and left `drill` as
`null` forever — since the component's only "no drill" render path is the loading skeleton, a failed
fetch looked identical to "still loading," forever. Same severity class as 2026-07-23's `HomePage.jsx`
feed-load fix (primary content silently going into a permanent, misleading state), but a stuck
skeleton is arguably worse since it never resolves into any terminal state. Added an `error` flag and
a distinct "Couldn't load this drill." card so the failure is visibly terminal rather than an endless
spinner.
