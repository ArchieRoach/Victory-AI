## Task 2: Security Audit

No commits landed on `main` since 2026-07-24's maintenance merge, so re-verified the existing
surface rather than re-litigating it: auth coverage on all 114 route handlers unchanged from the
intentionally-public set (register/login/logout, `/webhook/stripe`, static reference data,
`/health`, `/waitlist/signup`, `/ads/*`, `/onboarding/*`); CORS still an explicit allowlist; no
hardcoded secrets; VAPID keys correctly loaded from `os.environ.get`, not hardcoded.

**Fixed — `POST /push/subscribe` had no rate limit:**
This endpoint (and its `usePushNotifications.js` frontend hook) predates today but hadn't been
covered by a prior audit. It's correctly behind `get_current_user`, but `PushSubscribeRequest`
accepts an arbitrary-length `endpoint` string and `keys` dict with no rate limit, and upserts a
new `push_subscriptions` document per distinct endpoint value — the same unbounded-growth-via-
authenticated-spam shape as `/emotes/generate` (fixed 2026-07-24) and `/users/me/export` (fixed
2026-07-23). Added `_rate_limited(f"push_subscribe:{user_id}", 10, 60)`, matching the existing
convention. `DELETE /push/subscribe` wasn't touched — it only deletes the caller's own row by
endpoint, no growth vector.

`python3 -m py_compile backend/server.py` passes.

## Task 3: Debug Sweep

No `TODO`/`FIXME` found. All `.then()` chains without an inline `.catch()` (checked all 12 files
using `.then()`, including `SponsorBanner.jsx` which wasn't in prior days' file list) have a
`.catch()` on the following line, all intentional graceful-degradation for secondary/decorative
data.

**Fixed — `usePushNotifications.js` silently swallowed subscribe/unsubscribe failures:**
Both `subscribe()` and `unsubscribe()` only `console.error`'d on failure. Their two callers
(`PushPrompt.jsx` and `ProfilePage.jsx`) each handle the "permission denied" case with a toast,
but any other failure (VAPID key fetch erroring, `pushManager.subscribe()` throwing) left the
UI reverting silently — the "Enable notifications" button or the settings toggle would just flip
back with zero feedback. Fixed at the hook (root cause) rather than in each caller: added
`toast.error(...)` to both catch blocks, which both callers now inherit automatically without
needing their own changes.

catches (`FighterBuddyCreator.jsx`'s archetype fetch and `OnboardingFlow.jsx`'s partner-styles
fetch both already pair with `toast.error`; the avatar-generation and social-proof cases reviewed
2026-07-24 are still intentional best-effort/decorative) are unchanged.
